"Definition of done" (§30): a feature is released only with UI, API, authorisation, entitlement enforcement, state logic, audit,
realistic tests, documentation, monitoring and a support runbook. The six implemented sectors remain *Pilot*, not *Available*. Adapters, queue metrics and encrypted restore tooling exist; local restore evidence is recorded in `VALIDATION.md`. Actual provider/monitoring/notification/regional recovery evidence remains pending. Delivery and Customs are explicitly limited scopes; their remaining requirements are in `IMPLEMENTATION_BACKLOG.md`. Passing tests do not waive those release gates.

## Current validation

The acceptance suites run against both PGlite and PostgreSQL 16 (separate temporary database per test suite). `metrics.test` covers authenticated scrapes, bounded route labels and worker error counters. `npm run e2e` exercises the freight browser workflow, and `npm run e2e:delivery` exercises registration → courier invitation → delivery/POD/COD → cash handover → reconciliation → remittance → fee invoice. Browser workflows mutate a disposable development database; they do not validate real providers or production operations.

Tenant JSON export now includes transport, fulfilment, custody warehouse, delivery/COD and Customs operational records, plus entity/branch metadata and audit evidence. Authentication credentials and invitation tokens are excluded.
